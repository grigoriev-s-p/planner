# Планирование команд

Веб-приложение помогает собрать квартальный план работ команд, проверить его
выполнимость и понятно объяснить ограничения. Оно работает с задачами,
командами, инженерами, ролями, технологиями, зависимостями и доступным временем
сотрудников.

Проект рассчитан на квартал из шести двухнедельных спринтов. Интерфейс доступен
на русском языке и открывается в браузере.

## Что нужно для запуска

- Windows, macOS или Linux;
- Python 3.10 или новее;
- установленный `pip`.

Node.js, отдельная сборка фронтенда и база данных на сервере не нужны.
Интерфейс уже находится в папке `frontend/`, а рабочий каталог приложения
создаётся автоматически в `data/catalog/`.

## Быстрый запуск

Откройте PowerShell в корневой папке проекта и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn src.web.api:app --reload
```

После запуска откройте в браузере:

```text
http://127.0.0.1:8000
```

Для остановки сервера нажмите `Ctrl+C` в окне PowerShell.

Если PowerShell запрещает активацию виртуального окружения, можно один раз
разрешить её для текущего пользователя:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Либо не активируйте окружение и заменяйте `python` в командах выше на
`.\.venv\Scripts\python.exe`.

## Первый запуск и загрузка данных

Приложение корректно открывается и без данных. На странице «Планирование»
загрузите исходный Excel-файл с каталогом. Система сама:

1. находит таблицы в файле;
2. приводит названия и значения к единому виду;
3. проверяет обязательные поля, ссылки и зависимости;
4. показывает ошибки и предупреждения до изменения рабочего каталога;
5. добавляет новые записи в каталог и строит предварительный план.

Для загрузки нужны данные о задачах, трудозатратах по ролям, зависимостях,
инженерах, их навыках и истории команд. Если в файле есть только часть данных,
приложение объяснит, чего не хватает для построения плана.

После подтверждения загрузки рабочие данные сохраняются локально в
`data/catalog/catalog.sqlite3`. Эта папка не попадает в Git. Кнопка «Сбросить
данные» в интерфейсе очищает локальный каталог и позволяет начать с нового
файла.

## Как пользоваться приложением

### 1. Построить и утвердить план

На странице «Планирование» можно загрузить Excel или работать с уже загруженным
каталогом. Система создаёт базовый, текущий и лучший найденный варианты плана.
Для рекомендаций доступны действия «Применить», «Отклонить» и «Отменить».
«Применить все рекомендации» устанавливает сохранённый лучший вариант.

Перед утверждением можно увидеть, какие задачи войдут в квартал, когда они
будут завершены и какие ресурсы займут. После утверждения план становится
рабочим планом квартала.

### 2. Закрыть спринт и обновить оставшийся план

На странице текущего спринта фиксируются фактические результаты: завершённые
задачи, незавершённый остаток и доступность инженеров. После этого создаётся
черновик пересчёта оставшейся части квартала.

Если изменение ресурсов затронуло будущие задачи, для каждой такой задачи можно
отдельно выбрать: применить новое размещение или оставить прежнее. Система не
позволит подтвердить сочетание, которое перегружает инженера, превышает ёмкость
команды или нарушает зависимость задач.

### 3. Посмотреть команды и компетенции

На страницах команд и «Звёздной карты» видны роли, технологии и устойчивость
команд. Карта поддерживает выбор команды или всей компании, поиск инженера,
масштабирование и перемещение схемы.

## Что реализовано

### Каталог данных

- импорт Excel с предварительной проверкой данных;
- создание, просмотр и изменение задач, инженеров и команд;
- работа инженера в нескольких командах с отдельной долей доступного времени;
- архивирование сущностей с причиной и сохранением истории;
- безопасное удаление: до действия показывается его влияние на план и связи.

### Планирование квартала

- план на шесть спринтов;
- учёт Story Points (SP), ролей, часов инженеров, дат и зависимостей;
- строгий приоритет задач по `rung`;
- планирование многоспринтовых задач;
- отдельная ёмкость команды в SP и отдельная доступность инженеров в часах;
- распределение задач сначала между сотрудниками основной команды;
- привлечение другой команды только для оставшегося дефицита нужной роли;
- проверка того, что команда-владелец действительно выполняет большую часть
  задачи;
- понятные причины, почему задачу нельзя разместить в квартале.

### Рекомендации и изменения плана

- рекомендации по перестановке задач, переназначению команды и помощи другой
  команды;
- отдельные рекомендации для независимых действий и пакеты только для действий,
  которые нельзя применить порознь;
- применение, отклонение и отмена рекомендаций;
- сравнение базового, текущего и лучшего вариантов;
- проверка, что последовательное применение совместимых рекомендаций даёт тот
  же результат, что и применение лучшего варианта целиком.

### Фактические результаты и показатели

- фиксация результата каждого закрытого спринта;
- неизменяемый исходный план для честного сравнения с фактом;
- показатель выполнения обязательств спринта (Say/Do);
- показатель завершения инициатив квартала (PI Predictability);
- досрочное завершение многоспринтовой задачи с освобождением будущих ресурсов;
- перенос незавершённой работы без переписывания уже закрытых спринтов.

### Риски и развитие сотрудников

- Bus Factor: количество активных инженеров, которые покрывают роль или
  технологию;
- выделение критичных компетенций, зависящих от одного специалиста;
- отображение инженеров, покрывающих конкретную компетенцию;
- рекомендации по дообучению и найму для ролей и технологий, важных для плана;
- учёт обучения в будущих спринтах и последующий пересчёт плана.

## Страницы интерфейса

| Страница | Назначение |
| --- | --- |
| Главная | Краткий обзор текущего плана, рисков и показателей. |
| Планирование | Загрузка данных, построение и утверждение квартального плана, рекомендации. |
| Текущий спринт | Фиксация факта и подготовка пересчёта оставшейся части квартала. |
| Задачи | Список задач, зависимости, назначения и причины ограничений. |
| Инженеры | Профили, роли, навыки, команды, нагрузка и обучение. |
| Команды | Состав, ёмкость, загрузка и риски команд. |
| Звёздная карта | Наглядная карта ролей и технологий команды или всей компании. |
| Риски | Ресурсные и плановые риски с пояснениями. |
| Развитие | Рекомендации по дообучению и найму. |

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `frontend/` | Интерфейс: HTML, стили и JavaScript. |
| `src/web/` | Веб-сервер, API и хранение рабочего каталога. |
| `src/planning/` | Расчёт выполнимости, распределение ресурсов и квартальный план. |
| `src/replanning/` | Сравнение версий плана, фактические результаты и пересчёт. |
| `src/bus_factor/` | Расчёт устойчивости компетенций. |
| `src/development/` | Рекомендации по развитию сотрудников. |
| `src/data/` | Чтение, нормализация и проверка Excel-данных. |
| `scripts/` | Необязательные служебные команды для подготовки и проверки данных. |
| `tests/` | Автоматические проверки. |
| `dev_ui/` | Вспомогательный интерфейс для разработки и проверки сценариев. |
| `data/raw/` | Место для исходного Excel-файла при автономной подготовке данных. |

Папки `tests/` и `dev_ui/` сохранены специально для дальнейшего развития
проекта. `tests/` позволяют безопасно проверять новые изменения, а `dev_ui/`
даёт разработчикам отдельное место для быстрой проверки сценариев без изменений
в основном интерфейсе.

## Необязательные служебные команды

Если нужно подготовить CSV-набор из Excel вне интерфейса, поместите один файл
`.xlsx` или `.xlsm` в `data/raw/` и выполните:

```powershell
python scripts/prepare_dataset.py
```

Для проверки качества уже подготовленных данных:

```powershell
python scripts/data_audit.py
```

Эти команды не требуются для обычной работы через веб-интерфейс. Созданные ими
отчёты сохраняются локально и игнорируются Git.

## Проверки для разработки

Для запуска автоматических проверок дополнительно установите `pytest`:

```powershell
python -m pip install pytest
python -m pytest
```

При работе над отдельной функцией лучше запускать только связанные тесты, а не
весь набор.
